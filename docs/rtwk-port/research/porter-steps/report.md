## Гипотезы
1. Полный gate после каждого шага — **подтверждено**. Причина — бриф запуска оркестратора («after each green
   step: fmt, clippy --workspace, whole nextest, shards.py»), вопреки fleet-brief и process.md §A10; land-check
   потом гоняет то же. 18 % вызовов, 31 % времени.
2. Ожидание — **частично**: это реальное время сборки; ~280 лишних вызовов из-за таймаута Bash 120 с против
   `bgrun wait` 240 с, потом опрос файлов вывода harness.
3. Флейки — **отвергнуто** как крупное (~1 %). Три самых частых не в known-red.txt:
   startup::session::a_remembered_mode_opens_without_a_prompt (15), chat_live::a_tap_on_a_row_chooses_it (12),
   skeleton::running_shell_preview_keeps_its_output_when_completion_omits_it (8; починен при слиянии сегодня).
4. Разгон после перезапуска — **подтверждено, больше**: медиана 54 вызова до первой правки (~13 % всех).
5. Нагрузка — **подтверждено**: `acargo check` медиана 44 с (заявлено 2–7 с), scoped nextest 47 с (10–15);
   land-check nextest 59 с при load 26 против 336 с при 157. 8–10 porter'ов на 3 слота сборки.
6. Неудобства инструментов — **подтверждено, умеренно**: ~320 вызовов (sed BSD, нет timeout, nextest -q,
   bgrun «gone», summary.py 77 мин на переднем плане).
7. Новое: 1.05 вызова на ход — правило «параллельные чтения в одном ответе» не выполняется; 972 чтения — поиск
   символа (rg, потом sed -n).
8. Новое: передача на ~100 ходах не происходит — медиана прогона 225 вызовов, 1–7 компакций.

## Предложения (не применены), по экономии на шаг
- **E1.** Без полного gate на partial: только scoped-проверки; land-check — gate partial'а; полный gate один раз
  перед task_done (land-check.sh через bgrun). Правки: шаблон запуска, process.md §A4.2 и §A10, fleet-brief
  «Checks». **−16 вызовов, −8 мин.**
- **E2.** Инструмент `~/.cache/codexcli/sym A B C` — определения с file:line, сигнатурой и телом ≤25 строк,
  несколько имён за вызов, `--oracle`. **−10 вызовов.**
- **E3.** В checkpoint — список `read:` ≤8 диапазонов file:line, типов, открытых красных; перезапуск читает
  checkpoint + раздел пака + диапазоны одним вызовом, без повторного чтения SKILL/process. **−7 на шаг
  (−20 на перезапуск).**
- **E4.** Не больше 5 porter'ов в фазе сборки одновременно (process.md §A7). **−10 мин.** Решение человека.
- **E5.** bgrun: wait по умолчанию 110 с (в пределах таймаута Bash) + `bgrun run <name> -- <cmd>` (старт и
  ожидание одним вызовом); не опрашивать tasks/*.output. **−5 вызовов.**
- **E6.** Правило: до 4 независимых чтений за ход. **−3 мин.**
- **E7.** Исправить медленную форму scoped-тестов в codex-porter.md:92 и process.md:328 →
  `--test screens -E 'test(<page>)'`, `--test rules` перед коммитом.
- **E8.** Три флейка в known-red.txt (с bug-задачей), `--retries 1` для whole nextest porter'а.
- **E9.** Заметка про macOS в fleet-brief: нет `timeout`, BSD sed, `--cargo-quiet` вместо `-q`, cd в worktree,
  один cargo на worktree. **−2 вызова.**
- **E10.** Правило 100 ходов: убрать или перезапускать на 100 с read-списком E3. Решение человека.

**Итого E1–E9:** −40–45 вызовов (~30 %) и −20–25 мин (~50 %) на шаг при нынешней нагрузке.
