Архитектура tui-rtwk: сейчас и цель (проект ADR-013)

Замер на b2eeacb7c, 2026-11-23. Исследование tm arch-boundary (Opus).

Коротко

  • Диагноз подтверждён. core/src/screens = 42,2k из 63,5k прод-строк core (66%). Граница core/UI проведена между «моделью экрана» и «отрисовкой» (MVU), а не между «доменом» и «UI», как во Flutter. Поэтому каждая новая форма UI становится протоколом core↔view («дверью»).
  • Поправка: большая часть screens — честный домен. В UI должно уйти лишь 15–18% (≈6,5–7,5k строк).
  • Три рода состояния: домен (ответы сервера/host) · «что спросили» (параметры запроса как ключ ответа) · «что нарисовано» (курсор, вкладка, страница шторки, стек меню, свёрнутость). Первые два — core, третий — State виджета и контроллеры rtwk.
  • Цена связности сейчас: 48% UI-коммитов правили и core, 26% — хаб-файл core. WIP /plugins добавил 9 дверей; из них домену нужны 2.

IO-тест (правило границы): значение живёт в core, если это (1) ответ/факт сервера или host, (2) запись о запросе — тикет и параметры как ключ ответа, (3) его читает другой экран, поток или шаг жизненного цикла, (4) оно пишется наружу. Всё остальное — в виджете.

Кто за что отвечает (цель C)

частьотвечает заговорит с
hostapp-server in-process, конфиг, IOshell: Ingress ↑, RPC ↓
UI · services/shellединственный исполнитель эффектовcore: ingest ↑, AppFx ↓
core · app, threadsCodexApp, ThreadModel — один писатель, applyпроекции → UI (select/watch)
core · features/<f>доменные глаголы, каталоги, операции (Op, Remote), заметки, фактыUI шлёт Intent::Feature; читает FeatureStates
core · screensтолько домен экранов (query, range, listing)ScreenStates → pages
core · kitчистая логика без состояния: vim, paste_burst, история, упоминаниявызывается из UI как функции
UI · pages, sheetsэкраны; своё состояние отрисовки в Stateглаголы → core
UI · features/<f>шторка фичи: вложенный Navigator, TabController, словаглаголы → core.features/<f>
UI · widgetsобщие кирпичи; picker со своими list/layoutне знает core-экранов

Feature теряет Menu, Pick, Prompt, choose, picked, prompt_submitted. Закрепляется правилами-тестами (ratchet до 0): нет полей отрисовки в core, нет UI-типов в Feature, нет интентов-жестов в core, widgets не видят core::screens.

Переход (фичи не встают)

  1. ADR-013 + правила в режиме ratchet — ½ смены. С этого дня новый код без Menu/Pick/Prompt.
  2. Пилот /plugins: ядро из WIP, без дверей; шторка заново на Navigator + TabController — 1 смена.
  3. Общий select (stack, kept → шторка; Picked → глаголы) — 1 смена.
  4. Остальное по касанию: settings, dialogs, resume, pets, agents.

Тесты: ≈140 тестов core переписать, ≈143 шага фикстур; 2622 oracle-теста не меняются. /rename + /export (95826e191) можно сажать как есть.
